# AI 对话助手与参考帖知识库评估

日期：2026-10-01。本文为基于现有代码的实施评估，尚未新增对话或知识库功能。

## 结论

可以在现有 AI 路线助手上扩展。建议第一阶段做“绑定当天行程的对话 + 景点推荐 + 手动导入参考帖 + 修改预览”，先把建议到落地的流程打通。检索先采用本地文本索引，资料规模扩大后再引入向量检索。

现有排序、地点搜索、道路核算、版本检查和撤销功能可复用，但“增加景点”和“缩短路线”需要不同的评价规则，不能用路程必须下降作为全部建议的应用条件。

## 已有能力与缺口

| 目标 | 当前状态 | 需要补充 |
| --- | --- | --- |
| 优化当天路线 | 已支持单路线／同一天多路线排序，按交通时间或距离比较 | 自然语言目标、多轮追问与偏好记忆 |
| 保留必去地点 | 已支持固定各路线起终点、锁定地点相对顺序 | 必去／可替换、酒店、休息和用餐约束 |
| 推荐景点 | 已有高德搜索和 POI 详情服务 | 候选检索、推荐理由、同名地点消歧及加入方案 |
| 安排全天时间 | 目前只核算交通成本 | 出发与结束时间、停留时长、预约窗口、开放时间及来源 |
| 参考帖子 | 尚无正文、索引或引用数据结构 | 导入、整理、检索、引用和删除资料 |
| 对话助手 | 当前为一次生成式排序，没有会话记录 | 消息流、当前日期上下文、工具调用与独立会话存储 |

当前排序接口只允许排列已有地点 ID，不能新增或删除景点，也不能跨路线移动地点；限制为 8 条路线、40 个地点。候选必须通过结构校验，并由高德重新核算道路成本，编辑行程后旧候选失效。

## 建议的使用流程

1. 打开侧边 AI 对话面板，明确显示当前计划和日期。
2. 输入需求，例如：“明天少走路，保留酒店和植物园，再推荐两个适合拍照的地方。”
3. 可选择参考资料：粘贴攻略正文、上传文本资料，并附上原帖链接和自己的备注。
4. 助手读取当天行程和选中资料的相关片段，通过高德搜索确认候选地点，生成 1–3 个可比较方案。
5. 展示新增／移除／移动地点、路线变化、交通时间与距离、推荐理由和原文引用。
6. 用户选择应用。应用前再次检查计划版本，变更作为一次操作进入撤销历史。

对不明确的地点、时间或偏好，只追问会改变方案的内容。普通聊天和查询不改动计划；每个修改方案都有独立的“应用”入口。

## 最小可用版本

### 对话与受控工具

复用现有 AI 配置和 OpenAI 兼容客户端。应用负责组织上下文、工具执行、约束检查和结果落地，模型负责理解要求和提出方案。

| 工具 | 输入范围 | 输出 |
| --- | --- | --- |
| `get_day_context` | 当前计划与指定日期 | 地点、路线、城市、目标、版本 |
| `search_places` | 城市、关键词、范围 | 经过高德检索的候选 POI |
| `get_place_detail` | 候选 POI ID | 官方名称、地址、坐标 |
| `search_reference_posts` | 用户选中的资料、关键词 | 相关片段与来源 ID |
| `get_reference_excerpt` | 已命中的片段 ID | 可展示、可引用的原文 |
| `evaluate_candidate` | 结构化候选方案 | 路段成本、不可达、约束与未知项 |
| `propose_day_changes` | 经过校验的操作列表 | 可预览的待应用方案 |

不向模型开放任意 SQL、文件读取、URL 请求或直接保存计划的工具。服务端对所有工具校验输入、计划／日期／资料范围和次数。兼容接口不一定支持原生工具调用，需要探测能力，并支持通过受校验的结构化输出完成受控步骤。

新增景点必须引用服务端返回的 POI 候选，不接受模型自行填写坐标或声明地点已验证。遇到同名地点时先让用户选定。

### 参考帖知识库

第一阶段支持粘贴正文及 TXT／Markdown 文本导入，附原链接、标题、作者、发布时间和备注。只有链接而没有可读取正文的资料不能用于内容检索，可保留为书签并提示补充正文。

保存来源与分段正文，先按城市、主题和关键词检索。中文文本应采用中文分词或经验证可用的 FTS5 trigram 索引，避免直接使用默认分词器导致中文召回不足。为不同方案保留实际引用的片段 ID，点击引用能定位原文。

建议的数据表与字段：

| 数据 | 主要字段 |
| --- | --- |
| 会话 | 计划 ID、日期 ID、标题、更新时间 |
| 消息 | 会话 ID、角色、正文、工具结果摘要、用量 |
| 资料来源 | 来源 ID、原链接、标题、作者、发布时间、导入时间、正文、哈希、备注 |
| 资料片段 | 片段 ID、来源 ID、正文位置、检索文本 |
| 待应用方案 | 基准版本、目标日期、操作列表、核验结果、引用 ID、状态 |

在本地数据库中使用独立表和迁移管理，不把聊天与资料正文放入 `PlannerData`，避免每条消息都触发整个计划库保存和快照。先支持按计划关联资料，跨计划复用可后续增加。

第二阶段再考虑经用户指定的公开链接导入，抓取前校验站点和重定向，禁止访问本机／内网地址。无需自动读取社交账号、聊天记录或绕过登录限制。后续资料量增长时，加入 embedding 与关键词混合检索；向量只是派生索引，原文和引用关系仍保留。

### 方案核验与应用

- **纯排序**：保留现有“同样地点、约束有效、目标成本改善”的规则。
- **新增或替换景点**：比较用户目标是否满足，展示增加的交通成本与停留时间，不强制要求总距离减少。
- **时间安排**：没有开放时间、停留时间或预约来源时显示未知，不能声称已保证可行。第一阶段允许用户补充，第二阶段加入时间窗口校验。
- **数据有效性**：计划、日期、路线和地点 ID 均由程序检查；方案生成后行程发生变化时重新核验，不能覆盖新编辑。
- **失败处理**：地点不明确、道路不可达、限流或网络错误时保留原行程，允许修改方案后重试。

现有“高德来源”标记只代表坐标来源，不能证明景点今天营业、无须预约或推荐内容真实。帖子中的主观体验与高德地点信息应分别标明来源和时间。

## 开发阶段与验收

| 阶段 | 交付内容 | 验收重点 |
| --- | --- | --- |
| A：可用闭环 | 当天对话、已有路线排序、POI 推荐、手动文本资料检索、引用、修改预览与撤销 | 推荐地点可验证、引用可定位、旧方案不能覆盖新编辑、失败不改计划 |
| B：全天安排 | 停留时长、出发／结束时间、预约、休息、体力与预算偏好 | 明确硬约束与偏好，冲突可解释，交通与游览时间分别计算 |
| C：资料增强 | 混合检索、资料更新、公开链接导入、跨日调整 | 来源时效、删除后的索引清理、跨日约束、链接访问范围 |

UI 建议采用侧边对话面板，保留地图和当天路线可见；方案以卡片展示，避免用整段聊天文本承载应用操作。

## 性能与数据边界

现有高德预算为每分钟 60 次，单个 40 地点方案最多约 39 条有向路段，原方案与候选合计可能达到 78 次。因此不应每轮聊天重算完整道路矩阵：先用地点位置和偏好筛选候选，再对少量方案计算道路，复用现有缓存及请求合并。

每轮限制工具步骤、检索片段、上下文长度、候选数与超时，记录 token 用量。当前配置服务的费率未知时不猜测费用。需要取消按钮，取消后的迟到结果不能改变方案状态。

只向所配置 AI 服务发送当前日期所需信息和用户选中的相关片段；密钥不进入会话。帖子、地点名和模型回答均视为数据，不能凭其中的指令扩大工具权限。引用链接由程序从来源记录映射，不能由模型虚构。资料删除时同步移除派生索引，并处理历史引用状态。
