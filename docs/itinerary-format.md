# 行程格式与时间轴

只规划地点、时间、路线。沿用 `version: 2`，旧备份仍可导入。日期、路线、地点支持以下字段：

| 字段 | 含义 |
| --- | --- |
| `name` | 简短名称；不要拼接时间、地点链或攻略 |
| `address` | 地点的详细地址，和 `name` 分开；未知用空字符串 |
| `startTime` / `endTime` | 计划开始／结束时间，24 小时 `HH:mm`，未知可省略 |
| `endDayOffset` | `0` 当天结束、`1` 次日结束；跨午夜须明确标记 |
| `notes` | 备注、预订、缓冲与待确认事项，最多 2000 字符 |

路线含有序 `stops` 和路线内的 `mode`（driving / walking / riding / subway）。地点时间表示抵达至离开的停留安排；路线时间表示整个阶段。它们都是用户计划，不会替代地图计算的距离和预计道路耗时。每天的 `departureTime` 与地点的 `stayMinutes` 用于手动[计算行程](itinerary-calculation.md)。

每天按路线与地点的顺序显示一条地点时间线，自动连接前一段末地点与下一段首地点，使用后一段的交通方式；不跨天连接，隐藏或空路线会被跳过，继续连接最近的可见地点。原有路线分组和地点 ID 保留，算路时派生连续路径，不批量改写计划库。旧 `transfers` 的名称、时间、方式与备注迁入当天备注，导出不再产生该字段。

地图道路带方向箭头，图例可独立切换道路与非道路接驳；图例中的非道路连接线不计入总路程。地铁方案包含步行接驳，完整方案的距离和时间参与计算；市内公交、城际铁路与航班可记在备注中。

地图业务数据默认保存 3 天，浏览器与 SQLite 分层复用，过期后在下次使用时请求。旧版分类有效期统一迁移为 3 天，之后仍可在设置中调整或关闭。缓存依据方向、交通方式、坐标与地图配置区分；清空缓存后失效。底图图片仍由高德 SDK 和浏览器按服务响应管理。

兼容整理仅识别明确的 `时间范围｜标题｜备注` 或 `标题｜时间范围` 旧名称；完整原文保留在备注，无法确定的跨午夜时间保持原文。读取现有计划时改善展示，导入预览与导出时生成分字段结构，不直接批量改写用户数据库。

## 导入与 AI

“导入 / 导出”提供完整提示词和独立虚构示例。精简结构为 `{trip:{name,days:[{name,date,routes:[{name,mode,stops:[{name,address,startTime?,endTime?}]}]}]}}`（问号仅表示可选，不是 JSON 语法）。`id/placeId/order/color/visible/category/favorites` 可以省略，由应用补齐；已有 ID 保留，自动 ID 避开已有值。未知日期用空字符串，未知坐标省略或用 `null`，不得编造地图来源。普通 JSON 导入使用本地校验，支持 5 MB、全行程 2000 地点。

“一键匹配并导入”按独立的名称和地址批量搜索高德，同名同址的重复访问只搜索一次。只有唯一的名称及地址匹配才自动选用；没有地址时需要已指定城市且有唯一同名候选。歧义、地址不符、搜索失败的地点保留待确认，导入后进入确认窗口。已有待确认地点也可使用“一键批量匹配添加”。保留每次访问的 ID、次序、时间与备注；可撤销，取消或草稿/行程变化后不写入旧结果。

“AI 检查并整理”复用本机已配置的 OpenAI 兼容服务，限 20000 字符、80 地点。输入可以是 JSON 或文字攻略。点击时才发送本次输入，候选须经本地结构校验并预览，采用后还需点击导入；原始输入可恢复，失败或输入已改变时不会覆盖。

有效本地 JSON 的地点 ID、归属和顺序不得变化；AI 整理后的名称与地址会被采纳，原字段记录在备注。地图坐标、城市来源与收藏由本机程序保留，不发送给模型。文字或无法解析的 JSON 不能可靠匹配原坐标，输出地点统一待定位；模型结果的时间、地点数量、备注仍需对照原文确认。AI 没有地图、数据库或文件工具，原文只作为用户数据上下文。
